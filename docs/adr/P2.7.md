# P2.7: explicit video import and reconstructed-camera timeline

Status: Accepted on 2026-07-13. Checkpoints A and B are GO.

P2.7 is a desktop-control-plane and presentation change. It does not change
COLMAP, MapAnything, gsplat, SceneBundle, Gaussian PLY, or the Gaussian render
core.

## Checkpoint A — Easy / Pro video import

The window accepts a supported video at any drop position and presents a
full-window Drop Overlay. A transient import session probes the source
immediately on a Python worker thread. The session has no ProjectStore or
ArtifactStore reference, so preflight, parameter changes, analysis, and Cancel
cannot create a job, artifact, or project document.

Easy exposes only Preview, Balanced, and Quality. Choosing one runs the P2.6
automatic quality-aware selection and, after analysis succeeds, commits the
input and starts the unchanged pipeline.

Pro owns the video preview, playback head, play/pause and frame stepping,
inclusive In/Out points, all four P2.6 sampling modes, cost estimates, and the
quality thumbnail timeline. Source metadata is available as soon as preflight
completes. Configuration changes increment a session revision; the single
analysis worker abandons an obsolete revision and analyzes the newest snapshot
without blocking Qt. Generate is disabled until that snapshot is complete.

The trim is represented by inclusive `in_frame` and `out_frame` values. Frame
selection still uses the P2.6 scoring and coverage implementation, but runs on
the trimmed logical range and maps the result back to original source indices.
Extraction therefore retains durable source-frame identity.

Automated Checkpoint A coverage includes all existing sampling tests plus:

- an exact 60-frame selection from a 120-frame trim of the synthetic 150-frame
  video, with every result expressed as a source index;
- transient-session cancellation and temporary-analysis cleanup;
- Generate committing profile, trim, selection, and durable thumbnail paths.

Checkpoint A evidence will be stored in `docs/evidence/p27-easy-pro.png` and
`docs/evidence/p27-pro-workspace.png` after the real `testvid/001.mp4` GUI run.

## Checkpoint B — keyframe cameras

`camera_timeline.py` joins durable identities without positional guessing:

1. the P2.6/P2.7 `source_frame_index`;
2. `inputs/frames/frame_<source index>.png`;
3. the matching name in COLMAP `images.txt` and its real `image_id`;
4. the referenced camera in `cameras.txt`;
5. OpenCV cam2world, intrinsics, source image size, aspect ratio and derived
   vertical FOV supplied to the Viewer camera.

The joined timeline is persisted in the project snapshot after reconstruction,
so restart does not depend on an in-memory or list-position mapping. Selected
images absent from `images.txt` are explicitly `unregistered`, carry no camera,
and open their extracted image with `No reconstructed camera`. Rejected frames
retain candidate state and rejection reason.

The Viewer remains the P2.5 WebGL2 Gaussian implementation. COLMAP image ids
remain the durable identity, while the matching SceneBundle camera supplies
the same normalized coordinate space used by the trained Gaussians; the raw
COLMAP pose and intrinsics remain alongside it as provenance. Its existing
JavaScript bridge now exposes `setCamera`, `setCameraView`, `setFreeView` and a
read-only state snapshot. Camera View derives eye, forward and up from the real
cam2world matrix, uses the real focal lengths and principal point, and
letterboxes to the reconstructed image aspect ratio. Free View retains the
accepted orbit/pan/zoom/WASD behavior. The camera track is unchanged except for
a colored axis highlight on the active real camera.

The Postshot-style timeline is placed below the Viewer and provides thumbnail,
source frame and timestamp, In/Out, Selected/Rejected/Candidate,
Registered/Unregistered, rejection tooltip, playback head, horizontal
scrolling, zoom, previous/next/play and filters. Playback invokes the same real
camera transition as a click.

Changing profile, trim, sampling mode, count or interval marks retained ingest,
COLMAP, fallback, training, validation and export stage records `stale`. The
mapping is also marked stale and is withheld from the Viewer until regeneration;
no old artifact can be presented as current.

Automated Checkpoint B coverage validates the filename/image-id/camera-id join,
an unregistered selected frame with a null camera, exact intrinsics/pose delivery
to Viewer metadata, Web viewer camera/free-view bridge presence, trim
persistence across profile changes, and stale propagation.

## Real-video acceptance

`testvid/001.mp4` was probed as 154 frames at 59.94 FPS and 1920×1080. Pro
Target Count requested 60 before any job existed. Analysis selected 60 from 150
quality candidates. Generate sent exactly 60 PNGs to COLMAP; COLMAP registered
60/60 and passed its production gate without fallback. Preview gsplat produced
48,237 Gaussians and the unchanged validate/export chain succeeded.

After restart, the project restored In 0 / Out 153, Target Count 60, the
154-entry source timeline, 60 registered real cameras, selection states and
camera mapping. Acceptance playback repeatedly switched registered timeline
items. The captured Viewer state reports Camera View, COLMAP image 1, the real
1920×1080 size, normalized SceneBundle focal lengths 1332.105 / 1332.106 px,
and the matching normalized cam2world eye
`[-0.650068, 0.053936, -0.622481]`. The original COLMAP pose remains in the
durable mapping and is never used against normalized Gaussian coordinates.
