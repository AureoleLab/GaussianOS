# P2.5: product desktop and GPU Gaussian viewer

## Status

Accepted on 2026-07-12. This decision is limited to GUI, durable state
correctness, three-dimensional viewing and product usability. It adds no model,
does not change the accepted P1/P2 reconstruction or training chain, and does
not implement 4DGS.

## Viewer decision

The desktop remains PySide6 6.10.2 + Qt 6 + QML. The former QML Canvas was a
bounded XY projection of sampled means and could not represent perspective,
anisotropic covariance, SH view dependence or alpha composition. Extending it
would preserve the wrong rendering abstraction, so it was deleted.

The replacement is a Qt WebEngine component inside the QML layout with a local
custom URL handler and a self-contained WebGL2 renderer. No network service is
used. The control plane validates a SceneBundle and graphdeco-gs-v1 PLY once;
the embedded component reads the original PLY bytes directly. Python is absent
from the frame loop.

Each Gaussian keeps its means, log scales, wxyz quaternion, opacity logit and
all SH coefficients through degree 3 in an RGBA32F GPU texture. The vertex
shader applies `exp(log_scale)`, quaternion normalization/rotation, perspective
Jacobian covariance projection and eigen decomposition to produce a true
anisotropic screen ellipse. It evaluates Graphdeco real SH from the current
view direction. The fragment shader evaluates the elliptical Gaussian and
uses back-to-front alpha blending. Behind-camera primitives are culled before
projection, and pathological training outliers retain their anisotropy while
their maximum screen footprint is bounded to keep free-camera views stable.
Camera trajectory and the ordinary sparse
point cloud use independent geometry passes and independent visibility
switches.

The camera supports left-button orbit, right/middle-button pan, wheel zoom,
WASD movement, reset and robust automatic scene fitting. Full depth sorting is
deferred while the camera is actively moving and is performed once after 140 ms
of idle time. This avoids an O(N log N) JavaScript sort for every pointer event;
the previously observed 1 FPS interaction on 255,172 Gaussians returns to the
GPU draw rate while preserving the final sorted image after interaction.

The native `QQuickRhiItem + C++` route was considered. For P2.5 it would add a
platform compiler, Qt private/native graphics lifecycle and shader packaging
surface that was not present in the locked Python desktop. Qt WebEngine is
already shipped by PySide6 6.10.2 and supplies a mature, Qt-contained WebGL2
runtime, making it the lower-risk deliverable route without moving computation
onto Python.

## Durable state and GUI contract

Project documents retain sibling temporary writes, flush, fsync, same-directory
replace, bounded Windows sharing-violation retry and cleanup. All transitions
continue through the desktop control plane and the per-project re-entrant lock.
Restart recovery changes both a stale running project and its active stage to
`interrupted`.

Fallback is `skipped` whenever COLMAP passes its quality gate, including a
resumed cached COLMAP result. The fallback path retains `fallback_required` on
COLMAP and `succeeded` on fallback. Success normalization refuses pending or
running stages, and the GUI derives succeeded progress as exactly 100%.

The production layout is a compact top command bar, project/artifact browser,
central embedded viewer, profile/quality inspector and collapsible activity
log. It includes explicit empty/loading/error states, stage highlighting,
status colors, export access, viewer metrics and a single Fusion control style
to avoid unsupported native-control customization.

## Verification

Automated command:

```powershell
uv run --extra test --extra compatibility --extra desktop python -m pytest -q
```

Result: 91 passed, 2 skipped (the two opt-in external consumer validations).
Coverage includes shared-project concurrency, transient/permanent replace
failure, restart recovery, COLMAP success and actual fallback state, success
normalization/progress, Viewer success/error loading and Gaussian activation.

The real Scene 001 run was created from `testvid/001.mp4` through
`PipelineController.create_project/import_input/set_profile/run` with the
`balanced` profile. COLMAP registered 21/21 frames and passed its quality gate,
fallback persisted as `skipped`, and gsplat completed 3,000 steps in 260.30 s.
PSNR improved from 15.0246 dB to 22.9168 dB. Validation loaded 255,254
Gaussians through both ExportKit and gsply; export produced the SceneBundle,
the same Gaussian PLY consumed by the Viewer, and the COLMAP point-cloud PLY.

The Qt application was then closed and started repeatedly against the saved
project store. Every restart restored succeeded, 100%, fallback skipped and the
three view layers. The acceptance hook exercised orbit, pan, zoom and walk,
then oscillated the camera continuously for 1.8 seconds. It measured 60 active-
camera FPS on 255,254 Gaussians after the deferred-sort optimization. The real
window and activity log are captured in
[`docs/evidence/p25-001-viewer.png`](../evidence/p25-001-viewer.png).

The persisted run can be reopened with:

```powershell
uv run --extra desktop python -m apps.desktop.main `
  --projects <local-project-directory> `
  --artifacts <local-artifact-directory>
```

The exported PLY is byte-identical to the validated Viewer input; there is no
preview-only approximation asset.
