# ADR P1: core chain, contracts, and production candidates

- Date: 2026-07-12
- Status: **P1 not accepted / P2 blocked**
- Dataset: `sha256:152be2c9901a8652daa032ab5c35a65aaf3aa83fc1deb1a1afa41a2a2a3ab33d`

## Decision

Use COLMAP 3.13.0 as the production reconstruction default. Its official
Windows CUDA release, source commit, archive hash, executable hash, train-only
registration quality, subprocess isolation, and atomic artifact publication
were all verified on three scenes.

Keep gsplat 1.5.3 as the intended production trainer and MapAnything Apache
1.1.2 followed by COLMAP bundle adjustment as the intended automatic fallback.
These are **implementation targets, not benchmark winners**: neither completed
on this host. P1 therefore remains NO-GO and P2 must not start.

Faster-GS stays a production speed candidate. GLUEMAP, VGGT-Omega, and
ImprovedGS are research-only and fail closed under the production policy.

## Architecture fixed by P1

- The host imports only shared contracts and starts Workers with `shell=False`.
- Requests/results use strict Pydantic v2 JSON contract version `1.0.0`.
- Every attempt has its own directory, stdout/stderr, request, result,
  cancellation file, work area, and output area.
- Timeout/cancellation terminates the process tree. CUDA OOM and crashes map to
  explicit error codes and cannot crash the host.
- Workers never access a project database. Artifact files must exactly match
  declared relative paths, byte sizes, and SHA-256 values before same-volume
  atomic publication.
- SceneBundle v1 is the internal source of truth. PLY is export/import only.
- Cameras are OpenCV cam2world, +X right, +Y down, +Z forward.
- Gaussian tensors are float32 `means[N,3]`, `log_scales[N,3]`,
  `quats_wxyz[N,4]`, `opacity_logits[N,1]`, and `sh_coeffs[N,K,3]`.

## Interchange decision

SceneBundle uses a strict manifest, generated Draft 2020-12 JSON Schema, and
SHA-verified safetensors. Provenance includes input hashes, config hash,
upstream commits, weight hashes, code/checkpoint licenses, normalization,
scale, SH basis/order, quaternion order, and color space.

Exports are unambiguously named:

- ordinary point cloud: `*.pointcloud.ply`;
- Gaussian splats: `*.graphdeco-gs-v1.ply`.

Gaussian PLY is binary little endian with Graphdeco channel-major `f_rest`,
opacity logits, natural-log scales, and `rot_0..3` in wxyz order. Import rejects
wrong property order/count, wrong SH degree, trailing/truncated data, NaN/Inf,
non-unit quaternions, invalid activated scales, and unsafe opacity values.

The SceneBundle → PLY → SceneBundle round-trip passes. Independent Gaussian
semantic consumers gsply 0.4.6, SplatTransform 3.0.0, and Brush 0.3.0 load the
fixture; Brush also rejects a malformed negative control. `plyfile` is only a
GPL-3.0 compatibility-test dependency and is excluded from production.

## Environment and licenses

- RTX 5090, 32,607 MiB, compute capability 12.0; driver 591.44.
- Isolated PyTorch 2.9.1+cu130 includes `sm_120` and passed a real CUDA tensor
  smoke test.
- gsplat compilation failed honestly: CUDA 13 `nvcc.exe` and MSVC `cl.exe` are
  missing. The global cu126 PyTorch remains untouched and incompatible.
- The observed Gyan FFmpeg binary is GPLv3 due to `--enable-gpl
  --enable-version3`; it is allowed for local benchmark preparation but is not
  the approved production redistributable. Production is locked to an audited
  LGPL FFmpeg n8.1.2 build.
- All candidate commits, release/checkpoint hashes, and authoritative license
  links are in `third_party/locks` and `third_party/licenses`.

## Unresolved risks

1. Installing compilers may expose gsplat/CUDA 13 source compatibility issues.
2. MapAnything's 4.9 GB checkpoint and COLMAP BA bridge remain untested.
3. Faster-GS transitive dependency audit and Windows build are incomplete.
4. Research checkpoints have incomplete or non-commercial license closure.
5. No trained scene has yet exercised large-N PLY memory/performance limits.
6. No legacy or Postshot reference exists, so visual/UX parity is unknown.
