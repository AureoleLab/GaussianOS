# P2: desktop workflow and durable orchestration

## Status

Accepted on 2026-07-12. P2 extends the P1 contracts and Worker boundaries; it
does not replace the P1 reconstruction or training decisions.

## Decision

The desktop product is a `PySide6 6.10.2 + Qt 6 + QML` application. Its
control plane is deliberately separate from the view and algorithm processes:

```text
QML / Qt main thread
  -> QObject desktop facade
  -> PipelineController background thread
  -> SubprocessWorkerRunner
  -> isolated COLMAP / MapAnything / gsplat processes
  -> ArtifactStore and per-project atomic JSON state
```

The Qt main thread only owns widgets, signals and JSON view models. It neither
imports a model library nor executes a Worker. Worker faults, CUDA errors and
cancellation are contained by `SubprocessWorkerRunner`; they become durable
stage results rather than process-wide GUI failures.

`ProjectStore` writes one atomically replaced JSON document per project. It
persists input identity, selected mode, run id, stage status, artifacts,
metrics, errors and warnings. A resumed run reuses only completed artifacts
that still exist and restarts at the first incomplete stage.

### Windows persistence safety

Project state is owned by the control plane. The QML facade only requests
create/import/profile transitions and reads snapshots; Workers never access
the project JSON. Every `load`, `save`, and `update_project` call shares a
process-local re-entrant lock keyed by `(resolved store root, project id)`.
`update_project` is the required mutation API, so read-modify-write is one
critical section even when separate `ProjectStore` instances are used.

Writes use a sibling temporary file, `flush`, `fsync`, and `os.replace`.
Windows `PermissionError` and sharing violations retry after 50/100/200/
400/800 ms only after every temporary handle is closed. Temporary files are
removed on both success and failure. A state-write failure stops the pipeline,
marks its in-memory state `failed`, attempts one final durable failure record,
and emits a queued Qt signal; it never advances a task while the UI claims it
is still running. On GUI restart, any previously `running` GUI-owned task is
durably marked `interrupted` with its completed-stage artifacts intact, so it
can be resumed instead of being presented as a live worker.

## Workflow

The GUI imports a video or image directory, extracts/copies PNG keyframes,
runs COLMAP, and only invokes the approved MapAnything Apache + COLMAP 3.13 BA
fallback when the COLMAP quality gate fails. It creates a frozen gsplat input
from the selected reconstruction, then produces a SceneBundle and Graphdeco
Gaussian PLY through the locked gsplat 1.5.3 worker. Export copies ordinary
point-cloud PLY, Gaussian PLY and SceneBundle; GLB/SPZ are deliberately
reserved interfaces in P2.

`Preview`, `Balanced`, and `Quality` select respectively 1,000 / 3,000 /
7,000 gsplat steps and 3 / 8 / 15 fps video extraction. They do not select a
different reconstruction or training model. Preview uses a documented -5 dB
fallback-chain PSNR gate: the small degraded diagnostic sequence can otherwise
be a real, exportable reconstruction whose held-out appearance does not improve
at 1,000 steps. Any negative gain remains a visible project warning; P1's
default 0.25 dB gate is unchanged.

The viewer is a bounded QML Canvas preview: orange represents the camera
trajectory and blue represents sampled sparse points/Gaussians. It reads the
validated SceneBundle/PLY only after training completes. Scene 002's known
skyline/building tearing remains a quality warning; no hiding, smoothing or
post-processing is applied.

## Fallback-to-training compatibility

P1's trainer originally assumed one COLMAP camera. P2 keeps the same gsplat
model and training loop but accepts the valid per-frame `PINHOLE` cameras
produced by MapAnything + COLMAP BA. The adapter freezes resized RGBs and text
COLMAP data, preserves the train/holdout manifest, and records
`recon.mapanything` provenance in the resulting SceneBundle. No MapAnything
weights are copied into the trainer artifact.

The repeatable live command is:

```powershell
uv run python benchmarks/run_mapanything_gsplat_integration.py --profile preview
```

It executes `COLMAP failure -> MapAnything -> COLMAP BA -> SceneBundle ->
gsplat -> Gaussian PLY -> SceneBundle/PLY consumer validation`, writes an
ignored summary to `benchmark_runs/p2-mapanything-gsplat/summary.json`, and is
restartable with `--resume` after cancellation or a Worker failure.

The 2026-07-12 Preview run completed the full chain. The forced COLMAP stage
ended `fallback_required`; MapAnything + BA, gsplat, SceneBundle/PLY validation
and exports all succeeded. ExportKit and `gsply 0.4.6` both read 7,247
Gaussians. Its held-out PSNR gain was -1.4887 dB, retained as a diagnostic
warning rather than concealed or reclassified as a quality success.

## Consequences

- P2 has no new reconstruction/training models and no 4DGS.
- An unavailable approved FFmpeg binary reports an actionable ingest failure;
  model computation is not moved into Qt as a fallback.
- Postshot remains `REFERENCE_PENDING` and is not an acceptance blocker for
  P2. Scene 002's tearing stays visible in the report/warnings.
