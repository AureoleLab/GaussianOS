# P2.9: unified Qt/QML visual system

Status: Accepted on 2026-07-23.

P2.9 is a presentation-only change. It does not change the Python backend,
ProjectStore schema, sampling algorithms, PipelineController, Workers, Viewer
renderer, WebGL scene format, or any durable data structure. Existing QObject
slots, signals, object names, and JavaScript camera bridges remain the UI
contract.

## Decision

The desktop now uses one global `DesignTokens` instance and a small family of
reusable QML controls. The appearance mode is `light`, `dark`, or `system` and
is shared by the main workspace, Pro Mode, Viewer shell, dialogs, sidebars,
timeline, log surfaces, and reusable controls. The dark background token is
exactly `#111111`; the semantic accent is Codex blue.

The token set owns:

- background, surface, raised/sunken surface, control and selection colors;
- primary, secondary, tertiary and disabled text colors;
- success, warning, error and information colors;
- spacing, restrained radii, control heights and typography;
- 120 ms, 170 ms and 220 ms motion durations.

`GfButton`, `GfComboBox`, `GfSpinBox`, `GfTextField`, `GfProgressBar`, and
`GfPanel` consume the same token object. Buttons use a dedicated centered
content container so Qt Controls cannot left-align their text when a layout
stretches the control. Combo boxes remain conventionally left aligned and
numeric fields remain right aligned.

## Page composition

### Main workspace

The light reference establishes the default launch appearance: compact native
toolbar, project/artifact rail, focused welcome canvas, status inspector,
pipeline stages, and an activity log. Borders and radii provide hierarchy
without card-heavy web styling. Empty, disabled, warning, loading, success,
and failure states use semantic tokens instead of page-local colors.

### Pro video import

Pro Mode is a full-window QML workspace rather than a small utility dialog. It
retains the real `MediaPlayer`/`VideoOutput`, playhead, frame stepping, inclusive
In/Out values, profile and sampling modes, asynchronous analysis, cost metrics,
quality timeline, Cancel, and Generate behavior. It can use any global theme;
the acceptance evidence uses dark mode to match the supplied reference.

### Viewer

The Viewer keeps the existing `gaussianViewer` WebEngine object and unchanged
WebGL renderer. QML supplies the themed project rail, inspector, sampling
controls, stage state, log, and keyframe camera timeline. The Web Viewer owns
its one functional camera/layer toolbar and its one operation hint; P2.9 does
not duplicate either in QML. This prevents overlay collisions without changing
rendering behavior.

## Interaction and accessibility

All reusable actions expose hover, pressed, keyboard focus, disabled, and
loading visuals. Semantic status colors cover success, warning, and error.
Buttons retain `Accessible.Button` roles and names. Ctrl+1, Ctrl+2, and Ctrl+3
switch to light, dark, and system mode; the header and Settings dialog expose
the same global appearance control.

Qt Layouts exclusively own the size of their managed children. Direct
`width`/`height` assignments on layout-managed items were removed to avoid
text drift and overlap at fractional display scale factors.

## Verification

Verification completed on Windows with PySide6 6.10.2 and Qt 6:

- QML lint loads `Main.qml` and every reusable component with no type or layout
  errors;
- real application captures at 100%, 125%, and 150% scale show no clipping,
  text offset, or panel overlap;
- Pro acceptance uses the real 154-frame `testvid/001.mp4`, producing 150
  candidates and 60 selected frames;
- Viewer acceptance loads the real SceneBundle, Graphdeco PLY, point cloud and
  449,917-Gaussian WebGL scene;
- the complete Python test suite, including the P2.9 QML contract tests, passes.

## Consequences

Future desktop pages should consume `DesignTokens` and the reusable controls
instead of introducing local palettes. Page-specific color is reserved for
semantic status and the 3D/image content itself. Any future Viewer chrome must
have one owner—QML or the Web Viewer—to avoid duplicate controls and overlays.
