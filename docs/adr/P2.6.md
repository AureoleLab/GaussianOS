# P2.6: deterministic video keyframe sampling

## Status

Accepted on 2026-07-13. P2.6 changes only video probing, frame analysis,
keyframe selection, sampling controls and provenance. The accepted COLMAP,
MapAnything, gsplat, Viewer, Gaussian PLY and SceneBundle schema implementations
are unchanged.

## Decision

The desktop control plane owns a new deterministic sampling stage before the
existing `inputs/frames` directory boundary. FFprobe scans the selected video
stream and records exact decoded frame count, duration, average FPS and source
resolution. FFmpeg then decodes every source frame once at a bounded analysis
resolution. Python computes only per-frame selection metrics; full-resolution
frames are decoded by FFmpeg after the indices have been chosen.

The four user-visible modes are:

- `Auto`: Preview/Balanced/Quality begin at 10%/20%/40% of source frames,
  bounded by profile minimums and maximums, then deterministic motion and scene
  change statistics adjust the target.
- `Target Count`: the requested final N is explicit. The candidate pool is
  `min(source_total, ceil(2.5 * N))` and N is never implemented as plain uniform
  subsampling.
- `Interval`: frame or second intervals create temporal anchors; the best
  acceptable nearby candidate is selected for each anchor.
- `All Frames`: every source frame is retained by explicit user request and the
  GUI warns about blur, redundancy and quadratic COLMAP matching cost.

The analyzer scores Laplacian sharpness, mean/clipped exposure, adjacent-frame
difference, low-resolution motion and a deterministic visual descriptor.
Severe blur, exposure failures and near-duplicates are excluded from the
quality pool. Candidate construction divides the complete source timeline into
bins before ranking quality, so a visually strong burst cannot consume the
entire pool. Final selection performs a second timeline pass and fills remaining
slots by combined temporal distance, descriptor novelty and quality. This gives
both time coverage and approximate viewpoint coverage while remaining stable
for identical input and configuration.

No seriously rejected frame is silently restored to reach N. If fewer than N
acceptable views exist, the actual count and rejection totals are persisted and
shown. Counts below 12 carry a reconstruction-risk warning. Large targets and
All Frames carry time, VRAM and redundancy warnings.

## Persistence and provenance

The `Project` document persists probe data, mode and interval configuration,
manual/Custom state, estimates, selected/rejected indices, thumbnail records,
warnings and the SHA-256 selection configuration hash. Changing input, profile
defaults or manual frame configuration invalidates completed stages and the run
id; an unchanged completed ingest may be reused only when its recorded
`selection_config_hash` matches.

The same required provenance object is written into
`training-input/dataset.manifest.json`, `training-input/sampling.provenance.json`
and the exported SceneBundle as `sampling.provenance.json`:

- `source_total_frames`
- `sampling_mode`
- `requested_frame_count`
- `candidate_frame_count`
- `selected_frame_count`
- `selected_frame_indices`
- `rejected_frame_indices`
- `selection_config_hash`

The SceneBundle entry is an additive provenance sidecar. This deliberately
avoids changing the accepted SceneBundle v1 schema or its tensor/format modules.

## Desktop experience

The profile inspector now reports source count, duration/FPS, resolution,
candidate count, requested/selected count and the actual completed ingest count
sent to COLMAP. Auto, Target Count, Interval and All Frames controls are
persistent. Manual changes display `Custom`. Cost/risk guidance is shown before
execution. A scrollable thumbnail timeline labels analyzed frames Selected or
Rejected and exposes rejection reasons; analysis runs outside the Qt main
thread and can be rerun without starting COLMAP.

## Verification

Automated selection tests construct a 150-frame video and cover targets
15/30/60/150, all four modes, frame/second intervals, deterministic results,
timeline coverage, blur/duplicate exclusion, insufficient-quality behavior,
N bounds, persistence/restart and exact extracted-directory counts.

The complete automated suite command is:

```powershell
uv run --extra test --extra compatibility --extra desktop python -m pytest -q
```

Result: 102 passed, 2 skipped (the unchanged opt-in external consumer checks).

Real-video acceptance used `testvid/001.mp4` with Target Count 60. FFprobe
reported 154 source frames, 2.581333 seconds, 59.94006 FPS and 1920×1080. The
quality candidate pool contained 150 frames and the final deterministic
selection contained the requested 60, spanning source indices 0 through 152.
Reanalysis produced the identical configuration hash and selected indices.

The existing Balanced pipeline then consumed exactly 60 PNGs. COLMAP registered
60/60 and passed its quality gate, fallback was skipped, and the unchanged
3,000-step gsplat worker completed in 242.96 seconds with 287,454 Gaussians.
Project status persisted as succeeded/100%. Both the training input and exported
SceneBundle contain the eight-field sampling provenance, and the GUI reports
`Sent to COLMAP: 60` after restart.
